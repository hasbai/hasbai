# 博客公开读取与缓存

当前实现采用私有 R2 公开内容快照。Neon 是内容主库，管理员读写仍经过原 JWT、GRANT 和 RLS。
本页负责缓存策略、成本边界和验收；内容模型见 [ARCHITECTURE](ARCHITECTURE.md)。

## 存储选择

2026-10-20 核对的免费额度如下。额度按账户和套餐共享，不是每个博客各享一份；本次不改变账户套餐。

| 服务 | 免费额度 | 当前用途与取舍 |
| --- | --- | --- |
| Workers | 100,000 请求/日；每次 10 ms CPU | 继续处理 SSR、公开查询与认证写入；不因内容缓存宣称请求或 CPU 免费额度不再计数 |
| KV | 100,000 读/日；1,000 写/日；1 GB | 保留启用语言配置；不存逐路径正文或扫描结果，避免低写额度和最终一致性的撤回延迟 |
| D1 | 500 万读行/日；10 万写行/日；5 GB | 不新增数据库或同步投影；当前内容小，无需再维护一套关系模型 |
| R2 Standard | 10 GB-month；100 万 A 类操作/月；1,000 万 B 类操作/月；出网免费 | 新建私有桶 `hasbai-blog-public-cache`，保存一份公开快照 |
| Cache API | 内容按机房存放，不提供持久存储保证 | 不叠加正文/HTML TTL 层，避免跨机房撤回失效问题；静态资源继续使用现有资源缓存 |

来源：[Workers](https://developers.cloudflare.com/workers/platform/pricing/)、[KV](https://developers.cloudflare.com/kv/platform/pricing/)、[D1](https://developers.cloudflare.com/d1/platform/pricing/)、[R2](https://developers.cloudflare.com/r2/pricing/)、[Cache API](https://developers.cloudflare.com/workers/runtime-apis/cache/)。

以目前 27,509 次 Worker 请求、每次 3 次公开读取的保守模型计算，约 82,527 次 R2 B 类操作，占免费月额度约 0.83%。这不是月末预测，也不含账户其他应用。常规读取不写 R2；只有内容提交、首次初始化、计划发布时间到达或快照超过 24 小时时重建。不要增加轮询或分钟 cron。

## 读取

- SSR 使用 SvelteKit 的请求级 `fetch`；浏览器导航使用相同的 `/api/public` 固定查询操作。
- 匿名 MCP 调用相同的快照查询函数。管理员 MCP 保持源库读取，可访问草稿。
- 每次公开查询读取当前 R2 对象。快照只在 Worker 内解析，接口只返回本次查询结果。
- 匿名 JWT 和 Neon Data API 仅在快照重建时使用，不再由访客浏览器请求。
- 重建经匿名 RLS 读取当前已发布内容，完整分页读取内容、译文、标签和关联。不保存草稿或未来正文。
- 查询保留语言回退、摘要列表、额外一条分页判断、标签、旧链接和搜索通配符。搜索不把用户输入拼入正则或 SQL。
- 未知内容返回空结果；页面继续按原契约返回 404。陌生 URL 不直接回源、不创建缓存键。
- `/api/public` 返回 `Cache-Control: no-store`，避免浏览器或下游另存旧正文；`X-Blog-Source: r2` 标识公开读取来源。
- `/studio`、认证、管理写入、MCP 协议响应不加入共享响应缓存。生产缺少 R2 绑定时返回不可用；无 Cloudflare 平台的单测和 Vite 夹具使用源数据替身。

## 更新与失败

原文 RPC 确认提交后、后续详情查询前立即刷新公开快照。每个已提交译文、删除内容和标签增删改同样刷新；浏览器删除和建标签改走认证 Worker 入口。语言配置继续读取 KV，不在正文快照复制配置，遵循 KV 传播语义。

刷新先将快照替换为带独立随机 revision 的失效标记，再读取匿名源数据。写标记和写快照均按旧 ETag 条件覆盖；冲突后重新读取源数据，不复用旧构建结果。排期列表保存在私有对象正文，不占用有界 customMetadata。R2 写入成功后，后续读取全球可见。[R2 一致性与条件写](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)

数据库提交和 R2 更新不是跨服务事务。确认数据库已提交、缓存更新失败时，管理端明确提示“内容已保存，公开缓存更新失败，请重新读取当前版本”。已写入失效标记的旧正文停止公开；后续公开请求重建，源库仍不可用则返回 503。R2 自身写入不可用时不能保证立即使旧对象失效，不能报告同步成功。

管理员提交会读取未来发布时间，只保存时间，不保存未来正文。首个到期请求重建快照并推进后续排期，无需后台保活。上线初始化须核对既有排期；本次初始排期为 0。取消排期后保留的旧时间只会多触发一次刷新，不会发布草稿。

24 小时刷新为外部直接修改 Neon 的兜底，不替代应用写后同步。外部维护后应通过应用的授权写入流程同步；不要把源库直写当作即时公开发布。每日刷新带来的 Neon 运行时间仍包含休眠等待，不能把快照命中率等同 CU 节省比例。

图片继续由图床的 R2 和现有 immutable HTTP 头负责。此改动不更改图床请求链路，也不声称图片 Worker 已完全脱离 Neon。

## 验收

必要回归覆盖热快照、未知 slug 零 Neon 请求，以及源分页完整性。其他检查包括草稿和未来正文隔离、语言回退、摘要分页与搜索通配符。更新检查覆盖到期发布、撤回、删除、快照失败和并发旧版本拒绝。RPC 成功后，即使详情读取失败，也须执行失效。生产核对 R2 来源头、SSR、导航、匿名 MCP 和对应自动部署版本；CI 与交付流程见 [TESTING](../TESTING.md)。
