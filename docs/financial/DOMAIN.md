# 报表口径

货币为人民币，时区为 `Asia/Shanghai`。所有计算只基于现有三表。

## 完整性与核心定义

- **完整交易**：必须具备至少两条正金额分录、科目齐全且借贷平衡。来源状态 `success`、`refund` 与 `partial_refund` 计入损益与现金流。`pending` 与 `cancel` 不计入。缺分录或缺科目的记录进入待补录（零分录不当作零金额完整交易）。退款按分录方向冲减。历史记录不自动合并或改状态（旧记录数见 [历史基线](history/DELIVERY.md#原始数据保持)）。
- **公式**：资产为累计借减贷。负债为累计贷减借。净资产为资产减负债。期间收入为收入贷减借。期间支出为支出借减贷。净收益为收入减支出（均保留符号）。
- **余额与损益**：`balance` 物化视图只排除同笔含缺科目分录，并包含全部已录入日期。`balance_history` 按北京时间日末累计至维护当天，无交易日承接前日。损益与现金流使用北京时间半开区间。历史无另存期初或自动结转。

## 现金流与同笔退款

- 现金范围为资产下「现金及等价物」子类。每笔完整交易计算现金借减贷（正值为流入、负值为流出、零值不增收支）。同笔现金户互转自动抵销，退款同笔冲减。分类优先级为：有收入或支出科目归生活，有非现金资产归投资，其余归筹资。同集合内期末减期初等于净现金流（`balance` 纳入范围更宽，两者不强等）。
- 首页默认显示所选月（截至月末或快照 `as_of` 较早者）。「未来 30 天」为 `as_of` 起 30 天半开区间内已录入完整非 `pending` 交易，不是外推预测。首页各卡片共用客户端固定的 `as_of`，不构成数据库单语句快照。
- **同笔退款**：以消费 100 退 30 为例。原 `transaction` 保留「借支出 100 / 贷银行 100」，并追加「借银行 30 / 贷支出 30」（净支出 70、净流出 70），随交易头 `occurred_at` 归期。

| 事项 | 净资产变化 | 现金变化 | 净收益 |

| 工资 10000 | +10000 | +10000 | +10000 |
| 银行消费 100、同笔退款 30 | −70 | −70 | −70 |
| 信用卡消费 100 | −100 | 0 | −100 |
| 信用卡还款 100 | 0 | −100 | 0 |
| 银行转钱包 100 | 0 | 0 | 0 |
| 借款到账 1000 | 0 | +1000 | 0 |
| 购买投资 500 | 0 | −500 | 0 |

合计净收益 9830、现金净增 10330（已在 SQL 测试验证）。

## 收入扣款与多账户录入

收支与转账只作为 `entry` 数组的编辑投影，不新增字段。例如工资 10000、个税 500、实收 9500 保存为贷收入 10000、借支出 500 与借资产 9500（净收益 9500、现金净流入 9500）。公积金归属通过资产分配或完整分录表达。多账户拆分保留各自金额与原 ID。只主动修改来源金额或移除行时，系统为单目标户重算余款。读取历史不重写金额。
