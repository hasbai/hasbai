# 按 commit 增量审计

沿用仓库已有的审计游标；无约定时使用根目录 `.doc-review-cursor`，记录上次完成审计的 commit SHA。

1. **确定区间**：记录开始时的 `HEAD` 为终点，检查工作区并保留已有改动。起点优先用用户指定值，否则用游标；两者都没有时检查最近 60 天并说明范围。验证起点存在且是终点祖先，无效时重新确定基线并说明覆盖限制。未提交内容单独检查、单独报告。
2. **识别变化**：查看区间内非合并提交和受影响文件。对比起止快照，覆盖合并引入的变化。关注功能、兼容性、使用方式、架构和设计规则的变化；重构、依赖、CI 等若影响已记载行为，也要检查。提交标题只作线索，以实际差异为准。
3. **选读并核对**：根据变化确定目标文档。未限定范围时，检查现存的 README、AGENTS、架构与设计文档及受影响的模块文档；限定范围时，只检查该范围和直接相关的共通文档。通读目标文档，即使提交没有显著变化也完成核对。重点检查能力说明、安装与使用步骤、示例、FAQ 和路线图。
4. **修正漂移**：按主 skill 的文档分工维护，只修正有依据的问题，保留目标要求。已交付事项移出路线图，在合适位置说明；确需补写但超出本次范围的大章节或教程，列为后续事项。
5. **更新游标**：审计和相关核验完成后，将游标写为开始时记录的终点。无需改文档时也更新；未完成不推进。

  保留游标的已有改动；若已被其他工作推进或修改，先核对再更新。按任务授权和仓库约定提交游标、建分支或创建 PR。只暂存本次改动；无文档变化时不制造 PR。
6. **报告结果**：报告审计区间、提交数、主要变化、修改文件、核验结果和游标状态。列出未解决差异或后续事项；创建 PR 时附链接。
